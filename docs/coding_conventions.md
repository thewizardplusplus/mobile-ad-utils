# Java coding conventions

These conventions apply to the plugin's public API and internal implementation, including private methods and local variables.

## Identifiers

Use `java.util.UUID` for identifiers generated by the plugin, including event and handle IDs. Keep externally assigned identifiers in the format defined by their provider. For example, the advertising platform supplies `adUnitId` as a `String`.

## Optional values

Every reference created, accepted, or returned by the plugin must be non-null. Use `java.util.Optional<T>` wherever absence is meaningful, including fields, local variables, parameters, and return values. Use `Optional.empty()` for absence and `Optional.of(value)` for a present value. Initialize optional fields to `Optional.empty()` whenever no value is supplied.

A method may also provide an overload that omits an optional argument. For example, `events()` uses the default scheduler and `events(Scheduler scheduler)` requires a scheduler. Convert nullable values received from an external SDK to `Optional` at the integration boundary using `Optional.ofNullable(...)`.

## Timestamps

Use `java.time.Instant` for timestamps throughout the plugin. An `Instant` identifies a point on the timeline independently of the device's time zone. Apply a time zone when formatting for local display. When an external format requires a numeric timestamp, convert at that boundary using the units specified by the format.
